# 需求定义

把讨论收敛为需要改变的现实及其满足结果。

## 需求树

根节点是 `谁需要改变 → 当前状态 → 必须发生的结果`；条件、取舍和假设是分支。

方案是候选手段；沿手段追到结果。逐项删除：删后根问题仍在，归方案；删后需求改变，归核心。标明事实、用户决定和推断。

## 前沿

前沿只含当前材料已出现、答案会改变根节点、价值排序、不可接受结果或边界的冲突与缺口。

每轮只问信息增益最高的一题。用具体冲突或失败情景呈现已有差异和答案影响；允许选择、组合、否定或重定义。推荐只依据用户已给出的优先级和事实。

核验可查事实；价值和边界由用户决定。每次回答后重画树、重算前沿。已回答分支保持关闭，直至用户改答或新事实与之冲突。前沿清空即收敛。

## 收敛

根节点完整、核心通过删除检验且前沿为空时，输出：`根目标`、`不可再删除的需求核心`、`已确认边界`、`尚未确定的假设`。

只保留会改变需求判断的内容。假设仅限当前材料已暴露、尚未确认且会改变根节点或边界的分支；没有则写“无”。用户确认总结即完成。进入下一阶段时，携带已确认核心并说明已离开需求层。
