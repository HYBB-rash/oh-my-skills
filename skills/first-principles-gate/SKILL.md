# 第一性原理阶段门禁

## 基线

证据集只含原始需求、已确认约束、权威条款、当前直接事实及来源。历史计划、产物、投入和旧结论列为待复核材料。

信息有限时按当前用户、个人或小型项目、当前用法、普通环境和可接受局部返工推导。工作和复杂度只来自证据集、实现目标的必要条件，或有直接证据的现实、严重且难恢复风险。

执行者先推导任务和最小阶段，逐项写明对应要求、必要问题和依赖事实；因果链成立时保留，失去依据时删除、重规划或 `STOP`。

## 一个逻辑门禁

1. **初审**：计划形成时启用一名新鲜、独立、能力充足的审计者。盲审包只含证据集和待核验问题；审计者先独立推导必要性、最小工作、关键假设和反例，再核验执行者的阶段、推导、产物与新增事实。
2. **冻结**：首次正式结论冻结本阶段的用户结果、授权、正式对象、外部动作、协议边界和可观察通过条件，并列全当前证据支持的阻塞。每项写明要求、直接事实或可达反例、因果链、最小修正或验证和通过条件。
3. **局部执行**：执行最小工作和低成本验证。新证据命中以下任一情况时，只打开最小相关条件：
   - 权威事实与冻结条件直接冲突；
   - 存在条件表面成立而用户结果仍为假的可达输入或执行轨迹；
   - 结果分类出现重叠、遗漏、不可达，或把查询失败当成确定事实；
   - 结论形成前可能越过冻结的读取、输出或副作用边界。

   schema、字段格式、解析、状态机、超时和测试问题留在本门禁内；命中上述条件时阻止收口，局部修正和验证后关闭，其余内容进入 `非阻塞备注`。
4. **有限收口**：在依赖阶段结果、进入下一阶段或执行关键外部动作前，由同一审计者只复查打开条件、必要回归、终态、时间一致性和协议边界。`REVISE` 后在同一位置局部修正和复查；全部条件关闭时 `PASS`。
5. **新门禁**：首次审计未预审的用户结果、授权、正式对象、外部动作种类或现实运行边界实质变化时，在依赖变化前开启新鲜盲审。已预审的条件性授权关闭原条件；既有对象的新事实映射到原条件。

审计者不可用时保持暂停或 `STOP`。整个流程留在当前会话，由当前执行者负责实施、暂停与继续。

## 结论标准

`REVISE` 只对应四类有证据的阻塞：

1. 当前事实显示任务或阶段已失去必要性；
2. 方案或冻结条件与已确认需求、约束冲突，包括可达反例证明条件不足；
3. 缺少会改变本阶段成败的决定性事实；
4. 直接证据显示下一步会造成现实、严重且难以恢复的后果。

每项达到通过条件后立即关闭。更严谨的方向、边缘情况、不改变判断的未知、惯例和未来设想进入 `非阻塞备注`。有界、易发现、可恢复的问题继续执行并记 To Do；严重风险只暂停受影响动作。抽样、预览、临时副本、一次性差异和局部回归可作最小验证。

## 输出与记录

- `PASS`：给出最短成立链、最强反证及其失效原因和非阻塞未知；只放行当前下一步。
- `REVISE`：给出完整阻塞清单和各项通过条件；只暂停最小受影响范围。
- `STOP`：给出任务失去必要性的事实链和重新开启条件；结束当前任务。

会话只记录证据集、冻结条件及状态、轮次和当前结论；恢复上下文时，历史计划和结论仍是待复核材料。
